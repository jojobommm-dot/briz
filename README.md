# Бриз

Сайт кафе «Бриз» (Пермь, Кировоградская, 12/2): банкеты, меню, обеды с доставкой,
позже — чат «вопрос-ответ» в реальном времени и приложение для гостей.

FastAPI + Jinja2, без сборщиков: CSS и JS лежат в `static/` как есть.

## Запуск локально

```powershell
python -m venv venv
venv\Scripts\pip install -r requirements-dev.txt
copy .env.example .env
venv\Scripts\python -m uvicorn app.main:app --port 8200
```

Сайт: http://127.0.0.1:8200

## Проверки

```powershell
venv\Scripts\ruff check app tests
venv\Scripts\ruff format app tests
venv\Scripts\python -m pytest -q
```

## Заказ обедов (приложение)

- `/zakaz` — экран заказа: доставка или самовывоз, день (ближайшие 5 рабочих), варианты
  комплекса с ценами, корзина, оформление в нижнем листе. Установленное PWA открывается сразу тут.
- Доставка на сегодня — до 11:00, самовывоз — до 14:00 (константы в `app/lunch_order.py`).
- Сервер сам считает цены и итог; заказ уходит в базу, гость получает ссылку `/zakaz/<token>`
  со статусом (обновляется сам), может отменить, пока заказ «Новый».
- «Мои заказы» и имя/телефон/адрес запоминаются на телефоне гостя (localStorage).
## Кабинеты

**Гость — `/kabinet`.** Вход по телефону и паролю (СМС-подтверждение — позже). Активные заказы и
история с «Повторить», сохранённые адреса (подставляются в заказ «пилюлями»), имя и пароль.
Заказы, сделанные с этого телефона до регистрации, привязываются сами — если совпадает номер.

**Менеджер — `/manage`** (вход `/manage/vhod`, сотрудники в таблице `staff`):
- «Заказы» — лента на день, кнопка следующего шага, отмена, звук и уведомление о новом;
- «Кухня» — что готовить: порции и выход по каждому блюду (гарнир отдельно), сколько осталось
  и сколько отдано, по времени к слотам, из чего складывается каждый вариант, упаковка;
- «Доставка» — по слотам: адреса, телефоны, состав, сколько получить с гостя;
- всё печатается. Нормы выхода порции — `LUNCH["portions"]` в `app/content.py`.

Сотрудники: `venv\Scripts\python tools/staff.py add olga "Ольга"` (также `password`, `disable`, `list`).
Первый менеджер создаётся сам из `MANAGE_USER`/`MANAGE_PASSWORD`.
- Оплата пока при получении; онлайн-оплата — отдельным шагом.

## PWA

Сайт ставится на телефон как приложение: манифест `/manifest.webmanifest`, воркер `/sw.js`.
- Страницы — сначала сеть, без сети — из кеша; главная, меню, обеды и контакты кладутся
  в кеш сразу при установке воркера. Незнакомая страница без сети — `/offline`.
- Версия кеша меняется сама при правке CSS/JS/манифеста — старый кеш чистится.
- `/manage` и `/api` не кешируются никогда.
- Android/Chrome — своя плашка «Установить», iPhone (Safari) — подсказка «Поделиться →
  На экран Домой». Плашка скрывается на 14 дней после «Не сейчас».
- Воркер работает только по HTTPS (и на `127.0.0.1` для разработки).

## Выкладка (Render)

Всё описано в `render.yaml`: сайт + PostgreSQL, каждый push в `main` выкладывается сам.
1. render.com → New → Blueprint → репозиторий `briz`; ввести `BASE_URL` и `MANAGE_PASSWORD`.
2. Свой домен: Settings → Custom Domains → добавить `briz.example.ru`, у регистратора
   домена завести CNAME на `briz.onrender.com`. HTTPS Render выпускает сам.
   После этого поменять `BASE_URL` на `https://` + домен.
- Бесплатный тариф засыпает после 15 минут без посетителей; бесплатная база живёт 30 дней.
- Диск на Render временный: заявки на банкет и кейтеринг (`data/*.jsonl`) пропадают при
  перезапуске — до переезда заявок в базу.
