# Бриз

Сайт кафе «Бриз» (Пермь, Кировоградская, 12/2): банкеты, меню, обеды с доставкой,
позже — чат «вопрос-ответ» в реальном времени и приложение для гостей.

FastAPI + Jinja2, без сборщиков: CSS и JS лежат в `static/` как есть.

## Запуск локально

```powershell
python -m venv venv
venv\Scripts\pip install -r requirements-dev.txt
copy .env.example .env
venv\Scripts\python -m uvicorn app.main:app --port 8200
```

Сайт: http://127.0.0.1:8200

## Проверки

```powershell
venv\Scripts\ruff check app tests
venv\Scripts\ruff format app tests
venv\Scripts\python -m pytest -q
```

## Заказ обедов (приложение)

- `/zakaz` — экран заказа: доставка, самовывоз или «в кафе ко времени», день (ближайшие 5 рабочих),
  варианты комплекса с ценами, корзина, оформление в нижнем листе. Установленное PWA открывается сразу тут.
- «В кафе ко времени» — гость заказывает заранее и выбирает, во сколько придёт и на сколько человек
  накрыть; к его приходу обед на столе. Цена — как в кафе, оплата после обеда.
- На сегодня — не позже чем за час до начала окна доставки и за 30 минут до самовывоза или
  прихода в зал: доставка до 12:30, самовывоз и зал до 13:30 (`MIN_LEAD` в `app/lunch_order.py`).
- Сервер сам считает цены и итог; заказ уходит в базу, гость получает ссылку `/zakaz/<token>`
  со статусом (обновляется сам), может отменить, пока заказ «Новый».
- «Мои заказы» и имя/телефон/адрес запоминаются на телефоне гостя (localStorage).
## Кабинеты

**Гость — `/kabinet`.** Вход по телефону и паролю (СМС-подтверждение — позже). Активные заказы и
история с «Повторить», сохранённые адреса (подставляются в заказ «пилюлями»), имя и пароль.
Заказы, сделанные с этого телефона до регистрации, привязываются сами — если совпадает номер.

**Менеджер — `/manage`** (вход `/manage/vhod`, сотрудники в таблице `staff`):
- «Заказы» — лента на день, кнопка следующего шага, отмена, звук и уведомление о новом;
- «Кухня» — что готовить: порции и выход по каждому блюду (гарнир отдельно), сколько осталось
  и сколько отдано, по времени к слотам, из чего складывается каждый вариант, упаковка
  (только навынос), столы и гости в зале;
- «Выдача» — все заказы дня по времени: курьеру (адреса), на стойку самовывоза и в зал
  (стол на сколько человек), сколько получить с гостя; фильтр по способу — например,
  распечатать маршрут курьеру. Старый адрес `/manage/dostavka` ведёт сюда;
- «Заявки» — банкеты и кейтеринг с сайта: новые сверху, статусы «В работе», «Договорились»,
  «Отказ»; на вкладке — счётчик новых, о новой заявке страница зовёт звуком, как о заказе;
- всё печатается. Нормы выхода порции — `LUNCH["portions"]` в `app/content.py`.

Сотрудники: `venv\Scripts\python tools/staff.py add olga "Ольга"` (также `password`, `disable`, `list`).
Первый менеджер создаётся сам из `MANAGE_USER`/`MANAGE_PASSWORD`.
- Оплата пока при получении; онлайн-оплата — отдельным шагом.

## PWA

Сайт ставится на телефон как приложение: манифест `/manifest.webmanifest`, воркер `/sw.js`.
- Страницы — сначала сеть, без сети — из кеша; главная, меню, обеды и контакты кладутся
  в кеш сразу при установке воркера. Незнакомая страница без сети — `/offline`.
- Версия кеша меняется сама при правке CSS/JS/манифеста — старый кеш чистится.
- `/manage` и `/api` не кешируются никогда.
- Android/Chrome — своя плашка «Установить», iPhone (Safari) — подсказка «Поделиться →
  На экран Домой». Плашка скрывается на 14 дней после «Не сейчас».
- Воркер работает только по HTTPS (и на `127.0.0.1` для разработки).

## Статичная копия на GitHub Pages

Как сайт coffe: https://jojobommm-dot.github.io/briz/ — только страницы (главная, меню, обеды,
банкеты с калькулятором, кейтеринг, контакты). Онлайн-заказа, кабинетов, `/manage` и отправки
заявок там нет — вместо них «Позвонить» и «ВКонтакте». Собирает `tools/freeze.py`, выкладывает
`.github/workflows/pages.yml` после каждого push в `main`.
- Один раз: Settings → Pages → Source: **GitHub Actions**.
- Посмотреть копию локально: `venv\Scripts\python tools/freeze.py _site --base-url http://127.0.0.1:8300`,
  затем `python -m http.server 8300 -d _site`.

## Выкладка: свой сервер (основная)

Боевой сайт: **https://briz.bar** — на сервере Автодонора (2.56.241.120), рядом с ним, не мешая:

| Что | Где |
| --- | --- |
| Код | `/opt/briz` (git, пользователь `briz`), venv `/opt/briz/venv` |
| Настройки | `/opt/briz/.env` (права 600): `DATABASE_URL`, `SECRET_KEY`, `BASE_URL`, `MANAGE_*` |
| Служба | `briz` (`deploy/briz.service`): uvicorn на `127.0.0.1:8200`, 1 воркер, до 300 МБ |
| База | PostgreSQL на этом же сервере, база и роль `briz` (Автодонор — `razbor`) |
| HTTPS | Caddy: блок `deploy/Caddyfile.briz` в `/etc/caddy/Caddyfile`, журнал `/var/log/caddy/briz.log` |
| DNS | nic.ru: A-записи `briz.bar` и `www.briz.bar` → 2.56.241.120 |

Обновить до свежего `main` (бэкап базы, pull, зависимости, перезапуск, проверка):

    bash /opt/briz/deploy/deploy.sh

Бэкапы — в `/opt/backups/briz-*.sql.gz`. Логи: `journalctl -u briz -f`.
Пароль менеджера — `PROD_MANAGE_PASSWORD` в локальном `.env`.

## Выкладка: Render + Neon (приостановлено)

С 25.10.2026 сервис `briz` на Render **приостановлен** (suspend через API, не удалён):
https://briz-7exj.onrender.com отвечает 503, push в `main` туда не выкладывается. Вернуть —
Resume в панели Render или `POST /v1/services/srv-dba5l9qjnfac73ef7mpg/resume`.

Прежний адрес: https://briz-7exj.onrender.com — бесплатный тариф, засыпает без посетителей
(первый заход до минуты), база на Neon во Франкфурте. Для настоящих гостей не годится: долго
и персональные данные за границей (152-ФЗ).

Сайт — на Render (описан в `render.yaml`, каждый push в `main` выкладывается сам),
база — PostgreSQL на Neon: бесплатно и без срока.
1. neon.tech → новый проект (регион Frankfurt) → Connect → скопировать Connection string
   (`postgresql://…?sslmode=require&channel_binding=require` — так и вставлять, приложение
   само переведёт параметры для asyncpg).
2. render.com → New → Blueprint → репозиторий `briz`; ввести `DATABASE_URL` (строка из Neon),
   `BASE_URL` (`https://briz.onrender.com`) и `MANAGE_PASSWORD`. Таблицы создаются сами.
3. Свой домен: Settings → Custom Domains → добавить `briz.example.ru`, у регистратора
   домена завести CNAME на `briz.onrender.com`. HTTPS Render выпускает сам.
   После этого поменять `BASE_URL` на `https://` + домен.
- Бесплатный Render засыпает после 15 минут без посетителей, первый заход — до минуты.
- Диск на Render временный, поэтому всё, что должно сохраниться, — заказы, кабинеты, заявки —
  лежит в PostgreSQL.
